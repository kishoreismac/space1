Reverse scoring note

Phase 1 · Day 1 (within 24 hrs)

Score Triage

Apply range bands · Flag P1 · Detect cross-patterns · Brief VP Eng same day
Activity 1: Apply Range Bands

Score every dimension. Below 2.9 = P1. Decline >0.4 pts vs last cycle = P1 regardless of absolute level.

Auto-calculated below
Activity 2: Cross-Pattern Check

Detect: Low S+Low E (tooling harm), Low S+High A (toil), Low S+Healthy P (heroics/attrition risk).

Activity 3: Psych Safety Gate Q7

If Q7 sub-score <2.5 all other scores are biased. Replace Phase 4 workshops with 1:1 interviews.

Activity 4: Exec Summary

Send one-page summary to VP Engineering same day results close. Acknowledge scores, commit to timeline.

⚡
Decision Gate: Emergency vs. Standard Track

Any score below 2.0 → Emergency: 48hr deep-dive, journey mapping within 5 days. Scores 2.0–2.9 → Standard: investigation within 2 weeks. Q7 below 2.5 → replace Phase 4 with 1:1 interviews.

Phase 4 · Days 5–10

Journey Mapping Workshops

One half-day per team · 6–8 devs · Do NOT show scores first · 5-Whys on top friction points
Activity 1: Session Setup

Recruit 6–8 developers from lowest-scoring teams. No managers in the room. Run 4 sessions: Precision Ag, Supply Chain APIs, Seed R&D, ERP Integration.

MiroFigJam
Activity 2: Walk the Journey

Narrate a real recent ticket from assignment to deploy. Facilitator maps every step, tool, handoff, decision. Capture time at each step.

Activity 3: Annotate + Dot Vote

Tag steps: 🔴 Pain · 🟡 Wait · 🟢 Smooth. Each developer gets 5 dot votes for highest-cost pain points.

Activity 4: 5-Whys Root Cause

Drill into top 3 dot-voted pains. Distinguishes symptom from root cause. Root cause becomes the blocker registry entry and JTBD statement.

🗺️
Decision Gate: Confirmed vs. Symptom-only

Blocker confirmed in journey mapping + matched Phase 3 signals → 3-source validation, highest confidence. Confirmed in journey mapping only → run targeted data pull. 5-Whys reveals management/process root cause → route to non-AI workstream, not AI backlog.

Phase 5 · Days 10–14

Blocker Registry + AI Feasibility

Compile registry · Score 5-dimension feasibility · Classify: Quick Win / Strategic Bet / Monitor / Defer
Activity 1: Compile Registry

Each 2+ source validated blocker: SDLC phase, dimension, score, signals, developer reach, hrs/sprint lost, AI fit.

Activity 2: AI Fit Flag

Yes / Needs Investigation / No. "No" entries routed to non-AI workstream immediately. Preserves map credibility.

Activity 3: Score Feasibility

5-dimension matrix: Tool Maturity 25% · Integration 20% · Cost Efficiency 25% · Data Availability 15% · Dev Adoption 15%.

Activity 4: Classify & Sequence

>8.0 = Quick Win (now). 6–8 = Strategic Bet (PoC). 4–6 = Monitor. <4 = Defer.

🚀
Decision Gate: AI Backlog vs. Non-AI Workstream

Only AI Fit = Yes or Investigate enter feasibility assessment. No = management/process/org issues route to a separate workstream. This preserves credibility of the AI map with leadership.
