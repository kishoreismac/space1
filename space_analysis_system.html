Phase 1 · Day 1 (within 24 hrs)

Score Triage

Apply score range bands · Flag P1 dimensions · Identify lowest sub-questions · Share with VP Eng same day

Activity 1: Apply Range Bands

Score every dimension against the five range bands. Any score below 2.9 is flagged P1. Any decline >0.4 pts vs last cycle is P1 regardless of absolute score.

Excel Scoring SheetSPACE Dashboard

Activity 2: Cross-Pattern Check

Check for dangerous cross-dimension combinations: Low S + Low E (tooling harm), Low S + High A (hidden toil), Low S + Healthy P (heroics/attrition risk).

Pattern Matrix

Activity 3: Psych Safety Gate

Check Q7 sub-score. If below 2.5, all other scores are potentially understated. Flag for 1:1 interviews instead of journey mapping in Phase 4.

Sub-score Analysis

Activity 4: Executive Summary

Send one-page triage summary to VP Engineering same day. Acknowledge scores, commit to timeline. Visible response prevents survey fatigue.

Exec Summary Template
⚡

Decision Gate: Emergency vs. Standard Track

Any dimension below 2.0 → Emergency track: 48hr deep-dive, immediate journey mapping within 5 days. Scores 2.0–2.9 → Standard track: structured investigation within 2 weeks. Q7 below 2.5 → replace Phase 4 journey mapping with anonymous 1:1 interviews.

Phase 2 · Days 1–3

Open Text Analysis

Cluster Q10/Q20/Q40/Q50 themes · Apply 30% frequency threshold · Preserve verbatim quotes for Phase 4

Activity 1: Theme Clustering

Read all 4 open-text question responses. Group by recurring theme manually or using basic topic modelling. Count frequency: how many developers named the same theme independently?

Affinity MappingLDA Topic Model

Activity 2: Frequency Threshold

Apply the 30% rule: any theme mentioned by 30%+ of respondents is a confirmed blocker regardless of Likert scores. This converts individual frustration to systemic evidence.

Frequency Counter

Activity 3: JTBD Extraction

Extract verbatim statements that contain implicit JTBD framing. These become the raw material for agent design briefs in Step 3. Preserve exact developer language — don't paraphrase.

JTBD Template

Activity 4: Misalignment Check

Compare open text themes against Likert low-scores. If a theme appears frequently in text but NOT in a low Likert score, the Likert question missed the blocker — flag for Phase 3.

Signal Comparison
🔍

Decision Gate: Promoted vs. Investigate Further

Theme mentioned by ≥30% of respondents → Promoted: enters Phase 3 cross-validation as a candidate blocker. Theme mentioned by 15–29% → Investigate: run targeted 1:1 follow-up with 3 respondents before deciding. Theme mentioned by <15% → Monitor: note but do not promote to registry.

Decision Gate: Triangulation Gate (2+ sources required)

Survey alone is not sufficient evidence. A candidate blocker enters the registry ONLY when ≥2 independent signal types agree. Survey + Quant = promoted. Survey only = investigate further. Quant only (no survey signal) = targeted 1:1 interview before deciding. All 3 signal types = P1 fast-track.

Phase 4 · Days 5–10

Journey Mapping Workshops

One half-day per flagged team · 6–8 developers · Do NOT show scores first · 5-Whys on top friction points

Activity 1: Session Setup

Recruit 6–8 developers from the lowest-scoring teams. No managers. Run 4 sessions: Precision Ag Platform, Supply Chain APIs, Seed R&D Pipeline, ERP Integration.

MiroFigJamPhysical Whiteboard

Activity 2: Walk the Journey

Developers narrate a real recent ticket from assignment to deployment. Facilitator maps every step, tool, handoff, and decision. Capture time spent at each step.

Journey Map Template

Activity 3: Annotate Friction

Tag each step: 🔴 pain (blocks progress), 🟡 wait (delays without blocking), 🟢 smooth. Dot-vote: each developer gets 5 dots to place on highest-cost pain points.

Dot VotingSeverity Tags

Activity 4: 5-Whys on Top Dots

Drill into the top 3 dot-voted pain points using 5-Whys. This distinguishes symptom from root cause — the root cause becomes the blocker registry entry and JTBD statement.

5-Whys TemplateRCA Framework
🗺️

Decision Gate: Confirmed vs. Symptom-only

Blocker confirmed in journey mapping AND matched Phase 3 quantitative signals → 3-source validation, highest confidence tier. Blocker confirmed in journey mapping but NOT in Phase 3 signals → run targeted data pull before promoting. If 5-Whys reveals root cause is management/process (not tooling) → route to management workstream, not AI backlog.

Journey Map Excerpt — Precision Ag Platform Team (8 developers)

1

Pick up ticket (Jira) → read description

Avg time: 15 min. Smooth — ticket exists and is readable

2

Understand the affected service

Avg time: 3.5 hours 🔴 Major pain — 7/8 dots — "I have to read every file in the service to understand what it does. There's a README but it's 2 years out of date."

5-Whys root cause: No automated documentation or AI-assisted explanation tool. Developers rely on reading source code as primary understanding mechanism.

3

Write code and unit tests

Avg time: 4 hours. Smooth — once codebase is understood, actual coding is fast

4

Submit PR → wait for CI/CD

Avg wait: 38 min build + 24 hr review lag 🔴 Pain — 6/8 dots — "Half the time it fails for a test that has nothing to do with my change. I just re-run it."

5-Whys root cause: No test impact analysis — full suite runs on every PR. 22% of failures are flaky tests unrelated to the change.

5

Address review comments → iterate

Avg iterations: 3.2x. 🟡 Wait — 4/8 dots — "Review comments contradict each other across reviewers. No consistent standard."

6

Deploy to production

Avg time: 2 hrs (approval gate) 🟡 Wait — 3/8 dots — "Low-risk changes go through the same approval process as high-risk ones."

Phase 5 · Days 10–14

Blocker Registry + AI Feasibility Handoff

Compile validated blockers · Score AI feasibility · Classify: Quick Win / Strategic Bet / Monitor / Defer

Activity 1: Compile Registry

Enter every 2+ source validated blocker. Tag: SDLC phase, SPACE dimension, survey score, confirming signals, developer reach, time cost estimate.

Blocker Registry Template

Activity 2: Preliminary AI Fit Flag

Flag each blocker: Yes (clear AI tool exists), Needs Investigation, No (process/management fix). "No" entries route to non-AI workstream immediately.

AI Landscape Map

Activity 3: Score Feasibility (Step 2)

Apply the 5-dimension feasibility matrix to each Yes/Investigate entry: Tool Maturity (25%), Integration Ease (20%), Cost Efficiency (25%), Data Availability (15%), Dev Adoption (15%).

Feasibility Scoring Matrix

Activity 4: Classify & Sequence

Score >8.0 = Quick Win (start immediately). 6.0–8.0 = Strategic Bet (plan PoC sprint). 4.0–5.9 = Monitor. Below 4.0 = Defer. Sequence by dependency and team availability.

Classification Matrix
🚀

Decision Gate: AI Backlog vs. Non-AI Workstream

Only blockers with AI Fit = Yes or Needs Investigation enter the feasibility assessment. Blockers flagged as No (management quality, org structure, headcount issues) are routed to a separate workstream. This preserves credibility of the AI opportunity map with leadership.
